# B成员人工基线调度优化与喘振预警详细任务书

空压站多机协同智能调度项目  |  版本 1.1（按A模块新交接更新）  |  2026年10月18日

本任务书面向成员 B。你的职责是把空压站的运行状态和A提供的预测、健康结果，转换为**可解释、可检验的机组调度方案**；再评估方案的喘振及供气风险，形成与传统人工调度公平可比的结果。最终交给C的是可直接调用的Python函数、固定输入输出格式、配置、测试与版本说明；交给D的是有来源标签的图表数据、典型场景和指标计算口径。

实施顺序为：**确认接口与数据 → 建立人工基线 → 拟合机组性能与管网近似模型 → 建立调度求解器 → 评估喘振和切换过程 → 同工况回测/仿真 → 封装函数 → 联调交接**。本书列的是待执行工作和验收方式，不把A的阶段报告当作B算法已经实现的证据。

## 1 你负责什么，交付什么

### 1.1 职责边界

| 内容 | B负责 | 与其他成员的关系 |
| --- | --- | --- |
| 传统人工调度基线 | 固定规则、阈值、启停顺序、记录和评测 | A提供历史数据；D展示基线 |
| 机组与管网模型 | 流量、功率、比功率、可运行区间、压力近似和误差 | A的数据质量标记必须沿用 |
| 智能调度 | 开机组合、负荷分配、压力设定建议、约束和解释 | C通过Provider调用并做独立安全门禁 |
| 喘振评估 | 代理边界、裕度定义、低中高风险和局限 | C包装为MCP并决定是否可执行 |
| 优化对比 | 同工况人工基线与优化方案的能耗、压力、启停和风险 | D使用你的结果写展示与材料 |
| 控制下发 | 不负责PLC、人工确认或执行日志 | C负责后端、MCP、Agent和模拟执行 |

B不训练A的负荷预测和健康诊断模型，不建立C的后端和MCP，不直接下发控制指令。A已交付真实数据、预测模型和无监督健康接口；B先用其冻结的测试集预测表做回测，在线联调用两个正式函数。健康风险只是弱验证的提示，不能据此自动停机。

### 1.2 最终完成定义

对同一历史/模拟场景输入，B模块能一键给出人工基线、优化候选、约束检查、喘振风险、异常原因和可复算的对比指标；可行方案的机组流量、压力、备用和动作过渡均满足已冻结约束。若缺少关键数据或没有可行方案，明确返回 `INFEASIBLE` 或 `INSUFFICIENT_DATA`，不输出“看似安全”的控制建议。

## 2 当前仓库基线与算法边界

### 2.1 已确认的事实

本版以本地 `Competition-main/Competition-main` 新下载快照及《项目协作与A模块详细交接说明(1).md》为基线。该快照包含A的数据流水线、六张标准与特征Parquet、测试集逐点预测、三份模型、健康接口与报告；尚未见B的 `baseline/optimization/safety` 模块。快照不含 `.git`，用于核验；实际提交代码前须在正常Git克隆中创建B分支。交接说明所述提交 `3daebe7` 无法仅凭无 `.git` 的快照独立确认。

真实设备档案只有4、5号两台离心机，型号ZH1250-6，每台额定功率1250 kW、额定流量268.9 m3/min、额定压力0.66 MPa，总额定气量537.8 m3/min。历史数据为2026-03-12至2026-09-12，分钟级。早期数据报告记载总流量最大值约597.2 m3/min，超过总额定值；这可能是短时超额、测量偏差或口径差，不能自动把597.2当作持续安全容量，也不能为了拟合方便删除而不说明。

A的在线预测入口是 `air_station.models.forecasting.service.forecast_json()`，结果包含15、30、60分钟三点的 `predicted_flow/lower_bound/upper_bound`；它仍读取特征文件最后一行，不能用于任意历史时刻回放。A现在提供 `artifacts/metrics/forecast_test_predictions.parquet`（同名CSV亦可核验），字段为 `time/horizon_minutes/predicted_flow/lower_bound/upper_bound/actual_flow`，覆盖测试窗口，可作为B冻结回测输入。回测只用当前 `time` 当时可获得的预测、状态与健康信息，不用末行在线预测覆盖历史。若需测试窗口外回测，须另请A导出同口径预测。

六张Parquet已在新快照中：`station_timeseries/device_timeseries/events/maintenance/forecast_features/health_features`，另有预测测试集Parquet。A的健康入口 `health_json()`、正式样例、指标与报告也已提供；健康分属无监督弱验证，报告中4/5号故障期与正常期分离度为负，不能宣称可靠识别故障。`health_json()`同样只给最新运行点；历史调度回测如需健康限载时间序列，应请A提供按时刻冻结的健康结果，或把健康异常场景独立标为仿真，不得将最新风险等级回填到整段历史。

### 2.2 真实数据能做什么，不能直接证明什么

| 事项 | 当前可用证据 | B的处理 |
| --- | --- | --- |
| 基线功率、流量、运行状态和母管压力 | 原始与清洗后时序 | 可计算历史基线和误差 |
| IGV与BOV开度 | 实测运行参数 | 可作风险代理，但不能当成真实喘振边界 |
| 设备性能曲线与喘振线 | 档案未包含 | 用显式标记的经验/机理假设构建仿真代理；保留待厂家核验项 |
| 加卸载记录 | 原始列为空 | 只能按已冻结规则从状态、IGV/BOV或功率变化推断 |
| 预警与真实喘振事件 | 预警列恒零，没有喘振标签 | 不报告“真实喘振预警准确率≥90%” |
| 真实优化后功耗、压力 | 数据只有历史运行轨迹 | 对比中的优化后结果来自模型仿真；不能写成现场已节能 |
| “3号机振动偏高” | 真实档案只有4/5号 | 3号机只放在模拟场景；真实回放用4或5号机 |

历史数据是每分钟一条，不足以用真实记录验证“喘振提前30秒”。可以在独立高频仿真中测试30秒目标，但必须写 `validation_mode=simulation`。

### 2.3 必须先与A、C确认的六项口径

1. **时间与来源：** A原始时间是否为北京时间；所有 `as_of`、模型输出和回测切片统一时区。C决定外部API格式，B内部不得混用无时区字符串与UTC。
2. **供气需求：** 预测均值和区间上界如何形成调度需求。第一版建议使用区间上界或明确分位数做鲁棒需求；备用容量另计，不在C再重复叠加。
3. **备用容量：** 明确是“额外可用流量”还是“N-1单机失效后仍供气”。真实双机下，N-1可能经常不可行，不能暗中放宽。
4. **加载率偏离度：** 赛题“±10%”须明确相对什么目标加载率、用百分点还是相对百分比、对单机还是全站统计。
5. **压力合格带：** 早期材料建议0.55至0.66 MPa，但未见甲方确认。先配置成**待确认示例**，不要把它写成设备官方安全范围。
6. **安全阈值：** 允许加载区间、最短开停机时长、启停次数、健康限载、喘振风险门槛和切换顺序，由B提议，C共同冻结并保存版本；缺乏依据时标为仿真假设。

### 3.3 与C共同冻结的Python调用协议

下面是B建议接口，最终命名和数据模型由C维护的公共契约确认。两函数不能读取全局可变状态或直接访问控制系统，输入与输出要可JSON序列化。

```python
def optimize_dispatch(
    snapshot: StationSnapshot,
    forecast: ForecastResult,
    health: list[HealthAssessment],
    constraints: DispatchConstraints,
    *,
    policy_version: str,
) -> DispatchResult: ...

def assess_surge_risk(
    snapshot: StationSnapshot,
    candidate: DispatchResult,
    *,
    boundary_version: str,
) -> SurgeAssessment: ...
```

`DispatchResult`至少包含 `status`、`reason_codes`、`as_of`、`forecast_id`、`health_ids`、`model_version`、`policy_version`、`validation_mode`、`objective_components`、`device_actions`、`total_flow_m3_min`、`estimated_power_kw`、`pressure_setpoint_mpa`、`reserve_m3_min`、逐条约束的 `pass/margin/unit`、可读解释、耗时与建议的动作顺序。`INFEASIBLE`时不得伪造有效动作清单。

`SurgeAssessment`至少包含每台机的 `risk_level=low/medium/high/unknown`、`margin_value`、`margin_unit`、`margin_definition`、`boundary_source`、`boundary_version`、触发因素、限制建议、`validation_mode`。无法评价时用 `unknown`，不能把缺曲线自动视为low。

数据质量和状态异常应作为结构化错误，例如 `INVALID_INPUT`、`STALE_FORECAST`、`MODEL_UNAVAILABLE`、`INFEASIBLE_CAPACITY`、`SURGE_BOUNDARY_UNKNOWN`。B不得因求解失败返回上一次方案并标成功；可返回 `fallback_candidate`，由C再次安全校验和人工确认。

## 5 阶段B1 传统人工调度基线

**建议用时：1天。** 基线是对照算法，不是直接复制历史每个开停机动作：历史运行包含人无法知道的未来工况，直接把后验动作当成“人工策略”会使比较不公平。

### 5.1 第一版规则

配置化实现：运行机组优先保持、压力低于下限且连续满足条件时增载/启机、压力高于上限且连续满足条件时减载/停机、固定机组启停优先级、最小运行/停机时间、动作迟滞及负荷预测缺失时的守恒规则。规则中的数值阈值由历史正常工况与设备资料提出，再与C冻结，不硬编码为所谓官方值。

基线输入使用与优化器相同的 `snapshot/forecast/health/constraints`，但只调用传统规则，不窥视未来真实负荷。若要做“历史实际运行轨迹”第二基准，单独命名 `observed_operation`，与规则基线并列报告。

### 5.2 实现和检查

`baseline/rules.py` 输出开停、各机加载和设定压力；`baseline/evaluator.py` 记录动作原因、启停次数、压力越界、供气不足、能耗与不可行情况。先用简单例子证明低负荷时不会因1分钟扰动频繁启停，高负荷时不会在容量不足时无条件关机。

**输出：** `configs/baseline.yaml`、规则实现、基线报告、10个以上覆盖阈值附近/启停锁定的用例。

**验收：** 同一输入重复得到同一方案；阈值可追溯；基线与优化使用同一需求、备用、压力、安全约束和模型条件。

## 6 阶段B2 机组性能与管网近似模型

**建议用时：1至1.5天。**

### 6.1 数据分层

先从A的标准数据取运行且质量合格的记录，按设备、加载区间、环境与压力工况分层。计算每机 `specific_power = power_kw / flow_m3_min`，流量接近0时结果为空，不让除零污染拟合。启停瞬态、测量尖峰、质量无效和超额点单独标记；只在报告有依据时决定是否排除。

4/5号机虽然同型号，也要分别拟合或验证同一模型是否适用。用历史时间前段拟合、后段验证，报告流量/功率预测误差与有效区间。小样本区域使用保守包络，不外推节能。功率-流量关系可以从线性/分段回归开始，逐步加入加载率、排气压力、环境温度等；模型越复杂，越要证明比简单基线好。

### 6.2 容量与效率边界

设备铭牌额定268.9 m3/min，实测瞬时可能超过该值。`rated_capacity`、`observed_max`和 `validated_operating_max`分别存储。没有厂家说明时，优化允许的持续最大流量以保守配置为准；任何更高设定都标记需要设备核验。

确定每台机的最小稳定加载、可调范围和功率曲线。没有厂家曲线时，最小加载区间作为工程假设加敏感性分析；不能拿历史最小观测值直接认定无喘振安全。对于功率随IGV/BOV变化的近似，仅作仿真估算，真实生产可行性等待现场验证。

### 6.3 压力模型

用历史母管压力、供需差、管网特征拟合短时响应近似，或用带明确参数的简化储气/漏损模型。报告训练验证误差，并输出不确定区间。母管压力是系统状态，不能把“设置压力0.62 MPa”当成“结果必然0.62 MPa”；模型没有足够辨识能力时，只提供保守设定建议与压力风险，优化后压力合格率保留为仿真指标。

**输出：** `performance.py`、`pressure.py`、模型工件、误差报告和有效工况范围。

**验收：** 历史留出段的误差有数值且可复算；停机零流量不生成假比功率；超额/外推工况有警告，不可安全使用时禁止优化器输出可执行候选。

## 7 阶段B3 多机调度优化器

**建议用时：1.5至2天。** 先做能稳定复现的滚动优化，每5至15分钟更新一次；不要一开始加入强化学习。

### 7.1 决策变量和目标

两台机组只有四种开机组合，可枚举组合，然后在每种组合内优化各机流量/加载率与压力设定。若后续加入第三台模拟机，沿用同一算法但独立标记场景，不混入真实统计。

硬约束优先：预测需求、备用、单机可用容量、加载上下限、压力合格带、最大功率、健康限载、最短运行/停机时长、最大启停次数、喘振不进入高危区，以及切换全过程供气不断档。目标函数在可行域内最小化预计电耗，同时用配置化权重处理启停磨损、压力偏离、健康风险和喘振裕度。软权重不能抵消硬安全约束。

例如对每个可行组合，先以预测上界或约定风险分位数形成 `required_flow`，再在允许范围求每台流量；`Σ可用流量≥required_flow+reserve` 的定义须与第2.3节保持一致。若备用定义为N-1，则额外做单机失效校验，不把总名义容量减总流量当作N-1备用。

优化器输出每个组合的可行/不可行原因与分项代价。给C和D的解释包括：选哪些机、每机流量和加载率、为何减少/增加机组、当前需求与区间、功率预测、压力风险、启停代价、健康限制及与人工基线的差异。

### 7.2 切换与鲁棒性

终态可行还不够。输出动作顺序与每步可用供气：先确认替代容量，再启机和加载，再卸载/停异常机；每步记录母管压力预计最低值。若模拟反馈显示新机未就绪，停止后续停机动作。

预测区间未覆盖突发用气时做敏感性检查：需求加5%、加10%、单机降容和健康报警等。这里的5%/10%仅作压力测试幅度，非保证裕量；对场景来源与参数记录版本。

求解超时、无可行方案或数据不足时分别返回 `TIMEOUT`、`INFEASIBLE`、`INSUFFICIENT_DATA`。可附“维持现状”的备选建议，但仅当当前方案经过供气、压力和喘振检查才可标记可行；否则提示人工处置，不能声称安全回退。

**输出：** 优化器、约束检查、回退模块、候选解释和配置。

**验收：** 两台机组的每种组合都被覆盖；故意构造容量不足、高风险或健康限载时不会输出可执行方案；单次求解耗时目标≤30秒。

## 8 阶段B4 喘振风险与安全裕度

**建议用时：1天。** 设备档案没有厂家喘振曲线，也没有真实喘振事件。B先交付明确标记的代理风险评估，后续拿到厂家曲线再替换边界Provider。

### 8.1 两级边界

1. **历史运行包络：** 按机组、压力、IGV和环境工况统计稳定运行点的低流量区域，形成经验下包络。它只表示“历史少见的运行点”，不能称为真实喘振线。
2. **机理/工程假设：** 以厂家资料优先；缺资料时用设备特性和离心机机理构造示意边界，保存假设、参数、单位、来源和有效工况。阈值必须在配置中，并由B和C确认其演示用途。

`surge_margin`建议定义为相同工况下 `(计划流量-代理边界流量)/代理边界流量`，只在边界流量>0且同一压力/IGV/环境坐标系内计算。若采用其他定义，则写入 `margin_definition` 并升版本；不能跨定义比较百分比。

### 8.2 风险等级与阻断

按代理裕度、边界不确定性、BOV、IGV、母管压力波动和持续时长分级。采用低、中、高、未知四种输出；短时单点噪声可用去抖，但不能让去抖掩盖持续危险。高风险候选必须标 `safety_blocked=true`；缺少边界或关键测量数据应为 `unknown`，由C按安全策略拒绝或人工升级处理。

还要评估机组切换每一步的风险，不能只评估终态。运行实测点超出模型有效范围时触发 `OUT_OF_DOMAIN`，不做看似精确的裕度计算。

### 8.3 验证方式

用历史正常点检查误报趋势和模型稳定性，但没有真值标签时不计算真实准确率。构造可重复的仿真样例：接近代理边界、越界、压力突变、进气条件改变、传感缺失和BOV异常，并把“30秒提前”放在高频仿真内检验。报告仿真样本数、规则、提前时间和误报数；明确不代表现场真实喘振验证。

**输出：** `safety/boundary.py`、`evaluator.py`、阈值、仿真测试集、报告和逐设备评估接口。

**验收：** 高风险和未知风险按约定被阻断；风险等级可解释；真实、代理、机理和仿真来源不混淆。

## 9 阶段B5 同工况回测与指标报告

**建议用时：1至1.5天。** 评测脚本按冻结窗口、固定场景和版本运行，输出人工规则与优化器的并列表。不能拿不同时间、不同负荷或不同供气任务直接比节能率。

### 9.1 公平对比设置

两个策略使用同一历史负荷序列、同一预测输入、同一设备可用性、同一压力约束、同一能效模型、同一备用定义及同一时长。历史实际运行作为参考轨迹单列，不能让优化策略只在易胜的片段比较。报告全部窗口、剔除窗口和原因，以及可行率和供气质量；安全违约策略即使省电也不计“有效节能”。

对每个分钟步长，电量 `E_kWh=Σ P_kW × Δt_h`；气量 `V_m3=Q_m3/min × Δt_min`。系统单位气量电耗 `SEC=ΣE/ΣV`，同等供气量下节电率 `=(E_baseline-E_optimized)/E_baseline`。若压力品质和供气量不相等，先调整/报告差异，不把此节电率称为综合能效提升。保留每机和全站功率、气量、压力偏差、缺供量和过度启停等分项。

### 9.2 指标清单

| 指标 | 计算与展示要求 | 目标/证据类型 |
| --- | --- | --- |
| 综合能效/节电改善 | 同供气任务能耗或SEC改善；列出分母和单位 | ≥6%为赛题目标，优化后仅仿真 |
| 加载率偏离度 | 用第2.3节冻结的目标、分母和统计范围 | ≤±10%目标，仿真 |
| “大马拉小车”时长 | 满足冻结阈值的分钟数；计算 `(基线-优化)/基线` | 下降≥60%目标，仿真 |
| 供气压力合格率 | 落在已确认合格带的采样点占比 | ≥99.5%目标；优化后仿真 |
| 压力波动 | 相同窗口的标准差或峰峰值，单一口径 | 下降≥30%为赛题目标，仿真 |
| 启停/加卸载 | 启停以状态计算；加卸载为代理推断 | 标记真实/推断 |
| 喘振风险 | 低中高/未知比例、阻断数和仿真误报 | 不宣称真实准确率 |
| 求解时延 | 从函数入口到方案输出，含约束与序列化 | ≤30秒目标；C另测完整≤60秒 |
| 可行率与缺供量 | 每窗口可行/不可行和欠供m3 | 安全必须先于节能改善 |

固定至少低负荷、峰值负荷、快速上升、下降、单机异常、高喘振、单机容量不足、数据缺失八类窗口。主要结果按时间留出段汇总，单个演示场景结果另列。针对阈值、备用和模型误差做敏感性分析，不允许只展示达到目标的参数组合。

### 9.3 报告诚实边界

已有预测报告显示15/30/60分钟MAPE达到8%目标，但优于最佳 `lag_1` 简单基线的说法不成立；B同时保留A模型和简单持续性预测的调度对比。健康接口和报告已交付，但故障弱标签分离度为负；B只能称其为无监督风险提示，历史健康场景若无逐时刻评分则标记为仿真。

若能效提升达不到6%、压力合格率达不到99.5%或“大马拉小车”未下降60%，如实保留全部结果，分析容量限制、预测误差、性能模型误差及约束冲突，不修改阈值只为达标。

**输出：** `baseline_metrics.json`、`optimization_metrics.json`、逐场景CSV、`optimization_report.md`、`metrics_dictionary_b.md`与可重复评测命令。

**验收：** 每个数值能追溯到代码、窗口、输入哈希、版本与验证方式；D拿到的图表和B报告数字一致。

## 10 阶段B6 封装、测试与C集成

**建议用时：1天。**

1. 把 `optimize_dispatch` 和 `assess_surge_risk`封装为直接导入的函数，接收C契约对象，不通过全局文件路径猜测当前工况。配置路径从参数传入，默认相对项目根目录。
2. 返回结构化错误和原因。模型文件缺失、无效设备、旧预测、NaN、零流量、时间未对齐、超时和越界输入都要可理解。
3. 使用固定fixture写算法测试：约束不被软权重突破；逐机流量之和等于计划总量；关机流量与功率为0；高喘振被拦；两个请求独立；同一输入稳定输出。
4. 用A已交付的 `forecast_json()`、`health_json()` 和测试集预测表做联调；构造健康异常与喘振边界时，明确区分A无监督评分和B仿真工况。
5. 在C的容器环境运行导入、配置加载、样例求解与超时测试，留下命令和日志。C包装MCP后，B参与一次“预测→健康→调度→喘振→安全”的协议级联调。

**输出：** B模块代码、测试、依赖与配置、6类样例、`integration_B_to_C.md`、版本标签。

**验收：** C不读取B的notebook或手工复制结果即可调用；C能根据结果判断可行、不可行和风险；单次求解目标≤30秒且结果可重现。

## 11 阶段B7 两个典型场景与D材料

**建议用时：0.5至1天，与C、D共同联调。**

### 11.1 负荷下降节能调度

从同一初始状态出发，A给15/30/60分钟预测；B人工基线维持传统启停逻辑，优化器提出保留双机降载或经验证后单机运行的方案。B输出每步预计流量、功率、压力、喘振和过渡风险。需求或备用不允许单机运行时，必须保留双机或返回无可行节能切机方案；不能为了画节能柱状图强制停机。

### 11.2 设备异常安全重调度

真实回放用4号或5号机受限；“3号机振动偏高”只用专门的模拟三机配置。B需提供健康限载或退出的计算依据、替代容量、过渡动作和喘振评估。至少准备容量不足与喘振高风险两个负例；系统应清楚显示“无法安全自动重调度”。

### 11.3 D可直接使用的材料

一张算法流程图、一张人工与优化对比表、一张逐机负荷/功率曲线、一张喘振风险示意图、两段场景解说、常见质询答复。每张图注明时间窗口、设备、单位、数据来源、模型版本和“历史/仿真”标识。不能把代理边界画成设备厂家真实喘振曲线。

**验收：** C的Agent能解释B给出的原因；D可以完整重放两场景，并能正确展示无解与高危阻断；三个成员使用同一指标文件。
