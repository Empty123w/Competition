**物理容量限制 vs 算法控制缺陷**：
- **容量限制**：peak/step/fault 的需求（或需求+extra5%备用、或单机剩余容量）超过可用容量 → 必然缺供、压力跌破带、回退（维持现状），非算法缺陷；所有策略结果一致。
- **控制缺陷**：未见；normal/low 无容量受限时，优化策略达成 100% 合格率与显著低负荷/能耗改善。
- **B4 安全**：`fault` 场景优化器正确将 `quality_valid=False` 机组置为不可用（B1 未筛除 → 其 1.000 合格率是**假象**，运行了失效机组）。

## 3. 结论（工程场景验证，非现场达标）
- **压力合格率 ≥99.5%**：在 **normal / low** 两个非容量受限场景达成 **100%**；在 **peak / step（容量受限）与 fault（设备失效）** 未达成（0.26 / 0.62 / 0.67）。失败原因=**物理容量不足**（需求+extra5% 备用 > 2×268.9，或单机失效后容量不足），非控制缺陷。
- **压力波动下降 ≥30%**：在 **low** 场景达成 **≈89%**（0.0350→0.0039）；normal/peak/step 因 B1 与优化器行为一致（或无可行解）无变化；fault 因 B1 掩盖故障反而"更低"，**不作达标依据**。
- **综合能效改善 ≥6%**：normal 7.7%、low 22.3%、step 5.0%、fault 9.2%、peak 4.6%（同场景 vs B1）。
- **大马拉小车下降 ≥60%**：low 场景 bal 89.6% / LRB 79.2% / B3 73.8%；normal/step 视策略而定。
- **加载率**（仿真场景）：同历史结论，D3 由 LRB-t10 主导（见 `delivery/load_ratio_all.json`，仿真未单列）。

## 5. 质量守恒（显式记账，已修正）
原先对容量饱和场景仅做硬钳制，未记账 → 守恒残差异常。**最小修复**：`pressure_step_accounted` 显式记录
- 超硬上限的**安全泄压** `safety_vent_m3`；
- 低于硬下限的**未满足需求（储气耗尽）** `unserved_deficit_m3`；
- 钳制步标志 `clamp_high_steps / clamp_low_steps`。
守恒式：`净入流 − 储气变化 − 泄漏 − 泄压 + 未满足 = 0`（逐步恒等，且整段复算 ≈0）。

| 场景 | 质量残差(m³) | 安全泄压(m³) | 未满足缺口(m³) | 高压钳制步 | 低压钳制步 | 初始压→终端压 |
|---|---|---|---|---|---|---|
| normal | **0.000** | 0 | 0 | 0 | 0 | 0.600→0.593 |
| low | **0.000** | 0 | 0 | 0 | 0 | 0.600→0.596 |
| peak | **0.000** | 0 | 31,289 | 0 | 192 | 0.600→0.400 |
| step | **0.000** | 0 | 6,842 | 0 | 78 | 0.600→0.400 |
| fault | **0.000** | 0 | 31,291 | 0 | 42 | 0.600→0.400 |

- **无"靠裁剪制造合格率"**：硬钳制 [0.40,0.75] **均在合格带 [0.55,0.66] 之外**（`clamp_within_band_check` 断言），钳制只会产生**带外**样本；低压钳制的压力=0.40<0.55 → 计为**不合格**，不会虚增合格率。
- **各策略质量守恒规则一致**：B1/B3/bal/LRB 均走同一 `pressure_step_accounted`。
- **初始/终端储气公平**：四策略同 `p_init=0.600`、同需求序列（单元测试断言初始压一致）；同场景终端压一致（normal 0.593、peak/fault 0.400）。
- 新增质量守恒单元测试 6 项（逐步恒等、高压泄压、低压缺口、整段闭合、钳制在带外、初始压一致），共 **16 passed**。
