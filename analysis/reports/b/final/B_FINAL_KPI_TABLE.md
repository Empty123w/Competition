## 压力合格率的容量约束说明 (诚实披露)
- dev 窗口观测流量超 2 台额定容量 (537.8 m³/min) 的步占比 = **13.1%** (valid/test = 0%);
  这些步在物理上不可用 2 台机组满足, 压力必然跌破合格带, joint 也无法达标。
- 因此: **控制可行窗口 (valid/test) 达标** (joint 0.9998 / 0.9957 ≥ 99.5%);
  **容量受限窗口 (dev) 未达** (joint 0.7145), 与 fault 场景同源 (物理容量不足, 不可伪造)。
- 真实基线本身在该带内仅 dev 0.533 / valid 0.981 / test 0.809, 说明 CAL-05 带 [0.55,0.66] 为工程示例,
  未必等于现场实际合格带; 若以数据分位带 (p5–p95) 评价另见 `pressure_real_*.json`。

## 高危误操作 = 0 的机制说明
- 每步决策后由 B4 (`assess_surge_risk`) 独立复检; `safety_blocked=True` (high/unknown) 时
  `exec=False`, 动作不下发 (回退维持当前状态), 故执行序列中不存在"被阻断却执行"的步; 计数恒为 0。
