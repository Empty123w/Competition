## 1. 用气负荷预测接口（forecast_json）

签名：

```python
forecast_json(processed_dir="data/processed",
              config_path="configs/forecasting.yaml",
              model_dir="artifacts/models",
              horizons=None) -> dict
```

| 字段 | 类型 | 单位 | 说明 |
|------|------|------|------|
| status | str | — | 成功固定 `success` |
| model_type | str | — | 如 `LightGBM` |
| prediction_base_time | str | — | 基准时刻（ISO，本地无时区） |
| predictions | array | — | 预测项列表 |
| predictions[].horizon_minutes | int | min | **默认时域严格为 {15, 30, 60}**（来自配置） |
| predictions[].target_time | str | — | 目标时刻 |
| predictions[].predicted_flow | float | m3/min | 点预测 |
| predictions[].lower_bound | float | m3/min | 下界 |
| predictions[].upper_bound | float | m3/min | 上界 |
| elapsed_seconds | float | s | 推理耗时（目标 ≤ 10s） |

模型文件：`artifacts/models/forecast_{15,30,60}m.pkl`（**`.pkl`**，joblib 格式）；
另有 `forecast_{15,30,60}m.txt` 为 LightGBM 原生文本副本。加载 `.pkl` 需 `lightgbm` 依赖。

样例：`analysis/reports/phaseA4/forecast_interface_sample.json`
逐点预测：`artifacts/metrics/forecast_test_predictions.parquet`

## 2. 设备健康诊断接口（health_json）

签名：

```python
health_json(processed_dir="data/processed",
            thresholds_path="configs/health_thresholds.yaml") -> dict
```

**顶层字段必须且只能是四个**：`status, validation_mode, evaluation_time, devices`。

| 字段 | 类型 | 单位 | 说明 |
|------|------|------|------|
| status | str | — | 成功固定 `success` |
| validation_mode | str | — | 固定 `unsupervised` |
| evaluation_time | str | — | **UTC ISO 8601（以 `Z` 结尾）** |
| devices | array | — | 机组列表，稳定排序 `4#`,`5#` |

**每个设备对象必须且只能是九个字段**：

| 字段 | 类型 | 范围/取值 | 说明 |
|------|------|-----------|------|
| device_id | str | `4#`,`5#` | 机组编号 |
| health_score | int | 0~100 | 健康分 |
| risk_level | str | 正常/关注/预警/严重 | 来自 `configs/health_thresholds.yaml` |
| anomaly_score | float | 0~1 | 无监督异常分 |
| top_anomaly_factor | str | — | 主因描述，无则 `无` |
| current_value | str | 或 `N/A` | 主因当前值（含单位） |
| normal_range | str | 或 `N/A` | 正常范围（含单位） |
| trend_direction | str | 平稳/改善/恶化 | 趋势方向 |
| suggestion | str | — | 处置建议 |

样例：`analysis/reports/phaseA5/health_interface_sample.json`

## 3. 输出物理路径（强制）

| 内容 | 路径 |
|------|------|
| 预测指标 | `artifacts/metrics/forecast_metrics.json` |
| 预测逐点结果 | `artifacts/metrics/forecast_test_predictions.parquet` |
| 预测报告 | `analysis/reports/phase2/forecast_report.md` |
| 健康指标 | `artifacts/metrics/health_metrics.json` |
| 健康报告 | `analysis/reports/phaseA5/health_report.md` |

## 4. 评价口径

| 项 | 预测 | 健康 |
|----|------|------|
| 主要指标 | MAPE(目标≤8%)、MAE、RMSE、WAPE | 无监督：健康分分布、弱标签分离度 |
| 单位 | MAPE %；MAE/RMSE m3/min | 健康分 0~100 |
| 切分 | train 03-12~07-31 / valid 08-01~08-20 / test 08-21~09-12 | 基线 03-12~08-20；核对用故障弱标签窗口 |
| 可验证性 | 真实数据闭环，可回测 | 事件级弱验证；**无监督，不得声称故障分类准确率** |

> 健康风险为无监督提示，非真实故障定论；故障码 26 为两机同步弱标签，疑似站级共因。
